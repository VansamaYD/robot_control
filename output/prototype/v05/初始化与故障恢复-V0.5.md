# 初始化与故障恢复 V0.5

日期：2026-11-03。适用于当前SO-101五轴持勺原型的设计讨论。未连接硬件，未执行校准、写寄存器或使能电机。

## 建议

以外部机械锁止泊位作为日常开机参考，而非每天在锅边运动回零。初始化的目的，是建立可信的设备身份、坐标、状态和控制接管，不是让所有舵机转到零度。

三个概念分开：

- 关节校准：编码器读数、方向、零偏与真实关节角的对应关系。
- 工作坐标校准：机械臂底座、锅具、汤勺、泊位之间的空间关系。
- 每日启动：校验已有标定和当前状态，在泊位支撑锁止下原位接管，再等待显式启动。

## 官方接口核查与改造边界

[SO-101官方校准指南](https://huggingface.co/docs/lerobot/en/so101)要求建立对应姿态和关节范围。[驱动源码](https://github.com/huggingface/lerobot/blob/main/src/lerobot/robots/so_follower/so_follower.py)中的连接/配置流程假设手臂已经在可安全卸力的静止状态，配置可能在关闭扭矩的上下文中进行；断开行为也受卸力配置影响。不是所有connect/disconnect都只是串口开关。

因此厨房原型不能在悬空持勺时直接运行未经审查的自动连接/配置/校准流程。先在机械支撑有效时核对所安装的具体软件版本与电机固件，然后建立只读握手和显式接管流程。

官方默认从臂配置还包含第六个夹爪执行器。若本项目真的拆除了第六个电机，需同步改成五电机清单；不能伪造第六轴反馈或忽略缺轴错误。

STS3215位置反馈不等于可信的整臂绝对坐标。需核对具体电压/固件、单圈分支、零偏、方向、减速/装配关系及模式。[厂商资料](https://www.feetechrc.com/2020-05-13_56655.html)也描述了掉电后某些多圈状态不保留，不能依赖未经验证的跨圈记忆。

## 首次装配：只在冷台进行

1. **设备清单。** 记录物理设备标签、控制器/USB身份、各关节角色对应的ID、型号、减速比、电压版本和固件。ID不是序列号，两个机械臂可能使用同一组ID；型号码也未必区分全部电压变种。
2. **单电机设置。** 按官方装配流程逐个设置ID和通信参数，避免同ID总线冲突。按实物标签匹配供电，不由软件猜测电压版本。
3. **关节校准。** 在卸载热工具、机械支撑可靠、运动空间清空的条件下执行。手动移动时按对应教程关闭扭矩，支撑自重，不强掰通电减速舵机，不撞机械止挡。厨房的工作软限位应比可动全范围更窄。
4. **确认模型坐标。** 用几个已知姿态核对实际关节方向与URDF。区分原始编码器计数、LeRobot归一化数值、角度和URDF弧度；校准中位、编码器半圈和URDF零位不能直接画等号。
5. **工具与锅坐标。** 测真实勺口中心、法向、弯颈偏置、工具质量重心；冷态标定出流点。记录底座相对锅的完整变换，不只记录锅口中心的平移。锅位可用可拆定位附件限制，拍照标记用于辅助确认。
6. **泊位校准。** 在实际支撑/锁扣装好后，记录受支撑的五轴角度和独立位置参考。V0.4模拟泊位角不能直接作为实机上电目标。
7. **低速验证并存档。** 对冷态轨迹、停机、原位接管和落座/脱离进行验证。保存标定、工作场景、工具、软件版本与轨迹的关联。

首版不需要另买主臂或深度相机来完成初始化。优先投入可靠的泊位、工具定位、装配标记及测量。

## 每次开机：两段式启动

正常关机应先按V0.4流程倒回/退出，确认支撑承重、机械锁闭合和驱动禁止，再断开控制与电源。急停或意外掉电不能假设已经完成该流程。

### 第一段：只读确认，不运动

1. 确认实际处在泊位，机械锁和支撑有效；检查工具、线缆、锅位，保持运动禁止。
2. 建立受控的只读通信。避免高层SDK自动配置、改零偏、扫范围、复位或卸力。
3. 核对预期电机清单、ID角色、型号与设备身份，不向未知ID广播写入。
4. 多次读取实际位置及位置变化、告警、模式、电压、温度等所需状态。识别超时、缺轴、旧帧和模式不符；“读寄存器成功”不等于“没有电机告警”。
5. 比较本地标定与电机内标定，检查工具和坐标版本。若不匹配，进入维护，不自动将旧文件覆盖回电机。
6. 以正确分支解码关节角，并与独立泊位位置确认交叉检查。不用简单取模或最短角路径掩盖跨圈/装配错误。

### 第二段：锁止下原位接管

1. 在电机尚未产生危险动作、机械锁持续有效的条件下，将当前实测位置作为初始保持目标；核对设备允许的写入顺序及读回结果。
2. 检查模式、速度/电流等启动配置；不要默认设备上次目标已清除，也不要直接发送旧轨迹第一帧或五轴零角。
3. 以经过冷态验证的受限方式使能，仍不松锁。观察位置跳动、跟随误差、电流和告警，确认可以原位保持。
4. 无异常后进入“已初始化、仍锁止”的待机状态，等待工作参数确认及独立启动指令。
5. 人员与工具退出、隔离恢复、工作模型与轨迹匹配，显式启动后才由驱动接管载荷、释放机械锁、抬离托架，经V0.4返回路线到S。

写当前目标后使能是否会被固件/模式切换覆盖、上电时Goal_Position如何处理，都须核对实际电机版本并在冷台实测。此处是接管需求，不是已保证零跳动的寄存器指令序列。

## 开机分类处理

| 状态 | 允许的下一步 |
|---|---|
| 泊位锁止、反馈及标定均可信 | 准备锁止下原位接管，不能直接开工 |
| 标定/工具/身份不匹配 | 维护校准，禁止自动写零偏补救 |
| 缺轴、状态过期、告警或圈数不明确 | 保持禁止运动，只读诊断 |
| 不在泊位或失电后姿态未知 | 异常恢复；不能自动沿直线回K或回零 |
| 实物在泊位但编码器与记录不符 | 排查打滑、错轴、零偏、拆装及分支问题 |
| 锅位、液位、鸡包络或工具变更 | 原位接管与工作启动分开；相关工作轨迹必须重新确认 |

你在空间示意里选择过70mm液位、30mm鸡偏移，这与V0.4的80mm/50mm工况不同。这类调整应改变工作场景版本，不能把上轮取汁路线直接视为仍然有效。只有工况变了不一定要重做关节零位校准，但必须重新检查取汁深度、净空及工作轨迹。

## 异常掉电或故障后恢复

先处理热源和残汁、隔离人员，并由独立支撑/保持结构承担机械风险。连接前确认卸力不会造成坠落；不得依赖程序继续运行才能安全。

只读收集状态后，由受控的恢复流程在已确认的空间中移向支撑位。必要时拆下/倒空汤勺、在冷态重新定位或维护校准。人工整理只能在可靠支撑和明确的电源/运动隔离下进行，不能让手托着悬臂同时切换扭矩。

故障解除不自动重启；重新执行初始化与工作确认。普通“继续”不能代替恢复，掉电前最后一帧也不能证明当前姿态。

## 需要保存的配置

| 数据 | 何时应复核或作废 |
|---|---|
| 设备标签、ID角色、型号/固件/供电版本 | 换电机、控制器或接线 |
| 关节原始范围、零偏、方向、模型映射 | 换舵盘、拆传动、打滑、重新校准 |
| 底座到锅/泊位变换 | 挪底座、挪锅、换支架或泊位 |
| 工具安装、TCP、勺面法向、质量重心 | 换勺、改变夹持位置、拆洗后未重复定位 |
| 工作场景与停车能力版本 | 液位/鸡位置变化，载荷、速度或硬件更改 |
| 对应轨迹版本与验证记录 | 上述任一相关数据变化 |

标定文件、硬件设置和工作路线分别保存，使用内容版本或哈希关联；不能只看文件是否存在。轨迹下发前再次检查版本匹配。相机可以辅助判断工具/锅位，但不代替可靠的支撑、锁止和运动禁止。

## 本轮交付与限制

`initialization_gate.py`是离线初始化条件规范，区分维护、只读、异常恢复和“可准备原位接管”；工作启动另有独立门槛。它不连接硬件、不写寄存器、不使能、不松锁，也不是安全控制器。

已检查：正常泊位输入、标定不匹配、缺轴/无效/过期反馈、未支撑状态、跨圈角度、泊位偏差、场景不匹配和显式启动缺失。所有测试通过。硬件上电行为、读写顺序、扭矩接管和失电恢复尚待实测。

运行离线检查：`python3 output/prototype/v05/initialization_gate.py`。
