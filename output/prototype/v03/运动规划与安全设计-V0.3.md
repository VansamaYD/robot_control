# 豉油鸡浇汁机械臂：运动规划与安全设计 V0.3

日期：2026-11-03。用途：冷态原型设计与仿真讨论。本报告不是安全认证或可直接下发的实机程序。

## 本轮完成与结论

已使用官方SO-101新校准URDF中的五个运动关节变换、轴向与限位，建立FK和连续分支IK；夹爪开合不计作运动轴。建立自定义弯颈汤勺与锅、鸡包络，计算三个控制点各一条17.4秒循环。每条以50ms采样，共349个姿态，并以25ms、697个姿态复查。

三条路线在当前简化模型中均找到连续解，未出现筛查范围内的包络重叠。满足本轮提出的关节速度、加速度及数值加加速度上限。该结果仅表明这个具体安装位与假设工具值得做冷水样机。

没有完成：原厂网格级碰撞、完整底座/紧固件/电缆/灶台/排烟罩建模、执行器动力学、真实制动、热变形、液体晃动、剂量与实际落点、实机定位精度或食品工艺验证。不得将数值IK残差当成实机精度，或将正的静态间隙当成急停安全距离。

## 采用的工况

沿用用户在上一轮调整的尺寸：锅口400mm、深120mm，液位80mm；勺口50mm、深25mm；鸡向远侧偏移50mm。鸡身仍为260×180×150mm的保守包络，鸡的真实形状和高度未测量。

坐标定义：锅最低点为原点O，X沿鸡身长方向，Y正方向远离机械臂，Z向上。所有下表位置单位为mm；不是相对台面高度。

| 项目 | 坐标/尺寸 |
|---|---|
| 机械臂底座参考原点 | (0,-400,80)，底座绕Z安装角90° |
| 锅沿 | Z=120 |
| 鸡身最高包络 | Z=150 |
| P：取汁勺口中心 | (0,-100,75)，勺口在液面下5mm |
| S：高位中转 | (0,-100,195) |
| A：左侧控制点 | (-40,-20,195) |
| B：中间控制点 | (0,-20,195) |
| C：右侧控制点 | (40,-20,195) |

底座参考原点距锅中心400mm，距400mm锅口边缘约200mm。相对锅沿低40mm，不意味着能直接放在现有台面；需实测炉具高度和侧面空间，以侧支架调整，避开火焰、散热气流和人工操作区。

自定义工具相对第五轴旋转坐标系：勺口中心位于(-80,0,-90)mm；局部+X为勺面法向，先沿局部-Z伸出90mm，再沿局部-X下落80mm。它是一种尚未制造的弯颈金属勺/连接方案，不是现成SO-101夹爪。

A/B/C是勺口中心的运动学控制点，不是已标定的汤汁着落点。倾倒后真正出流位置、鸡表面落点和覆盖范围必须用冷水标定。

## 为什么安装位置与工具都需要调整

在最初底座(0,-360,40)、通行高度215mm的方案中，粗包络出现约20.5mm重叠，主要来自折叠后肩部附近的非相邻连杆；这可能包含近似过度保守，但不能直接忽略。另一些过近或过高的底座方案连取汁姿态的水平勺约束也无法满足。

通过对候选安装位置与关键姿态筛查，选出本轮(0,-400,80)、通行195mm的参考方案。并非底座越高、越近就越容易完成任务。安装位置、工具偏置、姿态约束应共同求解，而非先固定底座再要求机械臂勉强伸到目标。

模型未覆盖所有可行安装位，也未证明所选方案最优。

## 一勺的路线与时间

每次取一勺，只浇一个控制点；下一勺切换到另一个点。先用A/B/C轮流运行。不要先假设一勺能稳定分成三份。

| 阶段 | 时间/s | 动作与约束 |
|---|---:|---|
| 取汁停留 | 0.7 | P点勺面水平，停留充液；实际剂量另行标定 |
| 竖直抬勺 | 3.3 | P→S，保持水平；先离开鸡身侧面狭窄区 |
| 高位平移 | 2.0 | S→A/B/C，保持水平，跨越鸡身前已升到通行高度 |
| 定点倾倒 | 3.0 | 勺口中心不动，法向向+X方向倾45°；五轴协同补偿 |
| 等待滴流 | 0.7 | 保持倾倒姿态；仅时序假设，不代表汁已倒完 |
| 恢复水平 | 2.5 | 同一点恢复勺面水平，不在回程中突然翻勺 |
| 空勺返回 | 1.6 | 高位回S；残汁仍可能滴落，路径保持在锅口范围 |
| 取汁区下降 | 3.6 | S→P，水平下降，避开鸡身与锅壁 |
| 合计 | 17.4 | 三个点轮流一遍约52.2秒 |

本轮高度195mm是勺口中心高度。50mm半球形勺体最低点在最不利法向下最多低25mm，因此通行时最低点不低于170mm，比鸡身150mm包络高约20mm；还需考虑制造、摆放、挠曲和制动误差。

不要从取汁点低位直接横移到鸡身上方。本轮对一个实际求解的Z=120mm低位横穿姿态进行了反例检查，粗模型将其判为与鸡身包络干涉。

不要用“所有关节同时插值到终点”代替笛卡尔路径。本文先规定勺口中心和勺面法向路径，逐姿态求IK，再对关节轨迹检查限位、连续性和包络。关节插值后的TCP通常不是直线。

## 五轴如何配合

- J1底座：选择左右浇汁位置，并补偿工具偏置引起的位置变化。
- J2肩与J3肘：共同控制水平伸距与高度。
- J4腕俯仰：在升降和移动中补偿前臂姿态，保持勺口方向。
- J5腕旋转：实现翻勺，但工具偏置使它不能独自完成定点倾倒。

例如80mm的下垂偏置绕柄轴转45°，若腕部不补偿，勺中心可出现约56.6mm横向和23.4mm竖向位移。实际工具坐标不同，数值也会改变。必须把真实工具变换纳入IK，不能只给J5写一个角度。

五轴约束采用三维位置＋勺面法向，不强行指定完整六维位姿。法向固定时，剩余绕法向的朝向自由度仍受结构限制。装上导流嘴后还要检查导流嘴朝向是否可用；真正六轴在这方面更灵活。

## 本轮轨迹数值

| 指标 | 三条路线中的最不利值 | 解释 |
|---|---:|---|
| 每勺时长 | 17.4s | 自选的保守参考节奏，不是厨师标准 |
| 最大关节速度 | 约49.3°/s | 25ms复查结果；低于本轮提出的60°/s上限 |
| 最大关节加速度 | 约103.8°/s² | 低于本轮提出的150°/s²上限 |
| 数值最大关节加加速度 | 约584°/s³ | 采样与差分结果；不是控制器已保证的硬限值 |
| 到模型关节硬限位的最小余量 | 约7.2° | 实机零位、软限位、跟随误差须重新标定 |
| 粗包络最小额外净空 | 约7.5mm | 已先扣7.5mm设计间隙；粗模型表面距离约15mm |
| 估算肩关节最大重力力矩 | 约0.70N·m | 仅静力，假设工具100g、汁液33g，不含动态/摩擦 |
| 估算肘关节最大重力力矩 | 约0.56N·m | 同上 |

提取的URDF质量仅用作粗略静力估算。原夹爪质量不重复计入，自定义工具的真实质量、重心和刚度都未验证。需要依据实际持续力矩和温升决定是否升级舵机或减轻工具。不能把3N·m左右的堵转能力解读为0.7N·m长期循环必然可用。

30mL实际剂量、17.4秒循环，对应约103mL/min循环搬运量。它可能比人工浇汁慢，需与人工工艺比较。前期讨论中的8～10秒/勺应视为待验证目标，不作为已实现性能。

## 轨迹平滑和控制实现

每段位置及倾角使用五次时间缩放s(u)=10u³-15u⁴+6u⁵，段首末速度、加速度为零。每段停一下便于原型调试，代价是周期较长；没有优化为最快轨迹。

IK采用上一时刻关节解延续，失败就拒绝该路线，不在执行中随机切换另一条解分支。实际下发前还要检查校准后关节范围、奇异附近放大、实际伺服跟随和通信时间。

建议层级：

1. 上位机Python：人工设点、参数、路线生成、离线验证、记录。
2. 近端控制器：有界短段执行、速度/位置检查、看门狗、停止请求。尽量避免上位机单次发送一个很远的目标后失联仍持续运动。
3. 舵机总线：同步目标与状态反馈，读取位置、电流、温度、电压及错误状态；核对具体电压版本和协议。
4. 独立故障保持与停机电路：不能只依赖Python、浏览器、USB或相机。

如果后续用MoveIt 2，需要配置真实工具、场景和关节限制，给路径增加时间参数化与Ruckig等平滑；后处理可能改变路径，需要对最终下发轨迹重新碰撞检查。不是“MoveIt规划成功”就可以跳过实机验证。

## 安全设计：把停止后的行为也设计进去

### 机械与空间

- 刚性底座，工具防转、防松与二次防脱，电缆不穿过扫掠区。
- 将全部运动连杆、工具、线缆和支架的扫掠范围列为禁止人员进入区；当前动画骨架不是完整扫掠体。
- 热区金属件与驱动分开，挡汁件不能侵入路径，蒸汽保护不能导致舵机散热变差。
- 热汤阶段需要在相关关节失去驱动力时，仍能防止手臂坠落、腕部翻转与满勺倾覆的结构。配重只能降低负载，不能独立代替制动或机械保持。
- 旋转限位和支撑设计应避免失效时把热汁导向操作人员；接液范围覆盖潜在滴落和退出路径。

### 普通暂停、翻鸡请求、故障停机

| 情况 | 处理原则 | 恢复条件 |
|---|---|---|
| 普通暂停 | 按经过验证的减速方式停止并保持；未退位时不允许人伸手 | 状态有效且人工确认后继续 |
| 请求翻鸡/盖锅 | 在控制与防护均正常、人员仍在区外时，执行已验证的倒空与退出路线；停到专门停靠支撑位置后允许人工操作 | 人工重新确认鸡的位置与点位 |
| 人员进入、碰撞风险、跟随异常 | 停止危险运动并保持/制动，不继续完成当前浇汁或自动回原点 | 人工排查、重新确认位置及工具 |
| USB失联、上位机崩溃 | 近端看门狗触发停止；不依赖上位机再发停止指令 | 重新连接、读取当前状态并确认，不自动续跑 |
| 舵机过流/过热保护或断电 | 由独立保持结构限制坠落和翻勺；不能假设舵机仍有保持力 | 人工处理，不自动复位 |
| 挪锅、翻鸡、换勺 | 相关点位和工具标定失效，需要重新确认 | 人工确认后重新生成/验证路线 |

上表第一列两种正常流程也都需要实机验证，不能把动画的“暂停演示”按钮当成设备停机。

需要额外设计专门的停靠点和退出轨迹，既让开锅口，又能托住勺子/腕部。本文的17.4秒循环只演示锅内作业路线，没有将任意姿态到外部停靠位假设为安全。没有该退位流程前，翻鸡必须停机并按预定人工操作程序处理。

### 正间隙为什么仍不够

举例：某危险点以80mm/s运动，故障反应延迟100ms，能达到的减速度200mm/s²，则简单直线模型停止距离为：

80×0.1 + 80²/(2×200) = 24mm。

该例的参数是示例，不是SO-101实测值。它已经大于本轮粗模型约15mm的最小表面距离，还没加位置误差、结构挠曲和液体晃动。因此当前路线的静态筛查不能证明故障停止安全。

需要在实机测最坏响应与停止行为，降低危险区速度/允许跟随误差，扩大净空，并验证停止方式是否保持在已检查的路径上。不能只检查TCP速度，还要检查连杆扫掠速度。各关节分别急刹可能使TCP偏离原路径。

厂商对STS3215保护机制的说明包含过流时释放驱动力的行为；具体型号和固件应核对。因此“舵机有过流保护”与“满勺不会掉下去”不是同一件事。

原炉具仍由人工控制；机械臂急停并不自动关闭燃气或加热。这一版本不支持无人看护。

## 原型状态管理

上电读取状态 → 人工确认工具/锅位/起始姿态 → 就绪 → 一勺循环 → 下一个点。

任意阶段有不可信状态则转为停止/故障，不能盲目回原点。冷态点动设定起始姿态的流程应单独设计，不在锅边带满勺自动寻找零位。

示教、试运行、自动循环、人工翻鸡四种模式互斥。点位确认不是安全功能，普通视觉也不作为人员保护的唯一通道。

## 下一轮应做的验证

1. 完整几何：给当前模型补真实勺柄、夹座、关节壳体、底座、灶台和线缆；对整条轨迹做网格碰撞和扫掠检查。
2. 工具实物：做孔位样件、金属弯颈连接，测重量/重心/TCP，重新生成路线。
3. 冷态轨迹：空勺→少量冷水→目标冷水量，低速逐段验证；测实际落点，不以控制点代替。
4. 故障试验：在有人控制、冷水、接液和防护条件下，逐阶段验证暂停、失联、掉电及保护卸力后的实际行为。
5. 耐久与温升：完成相当于实际工序的循环，记录关节温度、电流、位置误差和螺栓/打印件变化。
6. 人工对照：比较每分钟循环量、覆盖、操作便利性；决定是否值得加快或升级机械平台。
7. 以上问题解决后，再开展有人看护的热汁工艺试验。

5000元可以优先支持冷态动作验证。若可靠制动/保持、隔热和工具加工超出预算，应明确将交付限定为冷态原型，不用软件限位冒充完整热态防护。

## 文件和复现

- `arm_model.py`：官方五关节几何的FK/IK，NumPy实现；只提取事实参数，没有复制完整URDF或STL。
- `trajectory_sim.py`：三条路线、简化碰撞筛查、数值关节运动及静重力估算。
- `search_mount.py`：参考安装位的关键姿态筛查，不是全局最优搜索。
- `trajectory_results.json`：50ms采样结果；是仿真输出，不能直接作为实机指令。
- `summary.json`：配置、阶段与指标汇总。
- `verify_motion.py`：连续性、限位、提出的数值上限、低位横穿反例以及25ms复查。
- `validation-25ms/`：加密采样复查输出。

运行：`python3 output/prototype/v03/trajectory_sim.py`，然后 `python3 output/prototype/v03/verify_motion.py`。
