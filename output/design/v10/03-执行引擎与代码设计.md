# 03 执行引擎与代码设计

## 核心不变量

1. 会话只有一个权威状态和一个运动控制所有者。
2. `simulation_tick`为整数；时间=`tick * dt`，默认dt=0.02s，所有物理更新依此执行。
3. 配置、状态、代码版本和控制代次独立；相机不属于运动配置。
4. 已取消运行的任何迟到消息都不能再产生动作。
5. 所有运动都绑定显式起始状态、模型/工具版本与检查报告。
6. UI展示、MCP读取和截图只消费不可变快照。

## 身份与控制权

`principal_id`标识本地操作者或MCP连接方；`control_owner`是持有者ID；`origin=ui|mcp`是来源；`operation=manual|program`是方式。不能把“program”和“mcp”当互斥所有者类别，因为MCP也能运行程序。

控制权使用`control_epoch`单调递增。手动租约有墙钟到期时间（即使暂停仿真也会到期）；自主作业启动时转为服务托管执行权，外部观察连接断开不取消作业。自主运行结束后释放，不能自动交回已失效的外部租约。

每个动作携带`run_id, control_epoch, action_seq`。撤销或重启改变代次；不能仅清空本地队列，因为旧消息可能仍在传输中。系统启动还生成`session_incarnation`，旧进程即便复用数字代次也无法写入新会话。

## 两个状态机

会话：`uninitialized → paused_ready ↔ running`；异常进入`fault`；编辑配置要求暂停并结束/分阶段保存活动作业。初始加载后始终`paused_ready`，运行请求通过校验后显式同时启动作业和时钟。

作业：`queued → running ↔ paused → succeeded|failed|cancelled`。`running → waiting_operator`表示阶段已到停靠等待点；后续阶段建立新作业，旧作业在确认交接时标记`succeeded`且`end_reason=phase_handoff`。被放弃则标`cancelled`。草稿和已校验是Program/Plan状态，不混入实际作业生命周期。

进入`waiting_operator`前，终止当前阶段脚本、撤销其动作能力并清空待发动作，记录已验证的停靠条件；会话冻结在暂停状态。旧作业可保持等待记录，但不继续持有脚本写入权。此时仅允许显式的操作者场景编辑事务；恢复请求原子地校验新配置/计划、结束旧阶段并启动新作业。普通暂停中的运行作业不具备这项编辑权限。

恢复故障只解除错误，不自动回零、续跑或换模型。服务重启把旧活动作业持久标为`failed/end_reason=service_interrupted`。

## 一次代码运行的时序

1. 保存工作副本生成不可变ProjectRevision；未保存时必须明确保存后运行，不暗中运行旧文件。
2. 服务核对入口、参数、场景和能力，预留运行ID；先获得控制权，拒绝并发竞争。
3. 检查幂等键与请求指纹，事务性创建Run/Job和运行清单；准备ScriptHost。
4. Python执行到SDK调用，发送候选动作和源码位置；宿主注入运行身份和能力。
5. 规划器基于不可变上下文生成轨迹；服务准入时再次比较配置与起始状态。在计算期间状态变化则拒绝或显式重算，不能复用旧计划。
6. 核心按dt执行，每步更新关节、取/倒汁和液体事件，产生新状态版本。
7. 动作成功时SDK等待结束；失败/取消返回结构化异常，异常被捕获也无法恢复已撤销能力。
8. 代码退出且所有动作完成才标成功；终态撤销能力、释放控制权、保存清单和结束原因。

## 程序、技能与动作

Program为流程入口与阶段参数；Skill为项目内带版本的函数；Action为受控基础操作。建议基础操作：`move_joints`、`move_tcp`、`wait_sim`、`read_state`。`scoop`/`pour`/`park`由可读技能代码组合基础动作与受控液体交互，不能直接赋值“勺已满”。

技能描述包含名称、版本、参数Schema、单位、坐标、适用工具、前置条件、产生的动作、正常退出和失败原因。自定义技能可新增组合逻辑，不可新增绕过核心的私有设备访问能力。

SDK内部统一SI。用户友好的`volume_ml`等接口在唯一入口显式换算，保存规范化SI参数；绝不按数值大小猜测单位。姿态使用位置＋单位法向，五轴不承诺任意完整姿态。

代码形态示例（接口草案，不可直接运行）：

```python
from skills.scoop import scoop
from skills.pour import pour

async def main(robot, scene, params):
    for index in range(params.rounds):
        await scoop(robot, scene.points["source"], volume_ml=40)
        await pour(robot, scene.points["back"], duration_s=3)
    await robot.request_flip(next_phase="after_flip", remaining_rounds=2)
```

`request_flip`由受信技能处理余汁和停靠，检查成功才进入等待；不允许脚本仅打印“已停靠”冒充条件成立。

## 暂停、单步、取消

暂停请求在完整tick边界生效，控制RPC立即由宿主挡住；纯计算脚本不配合时可终止并将作业失败，不假称已成功保存任意Python栈。由运行宿主在SDK/调试边界管理恢复；需要暂停任意计算位置不是首版承诺。

动作步进记录当前动作ID目标边界；技能步进记录调用栈目标深度，执行至该技能退出。若遇错误、等待操作者、取消或预算上限立即退出步进。二者执行过程中仿真时钟推进，完成后暂停。dt步进仅推进一次核心，不允许顺便执行完整技能。

取消默认采用明确标记的理想运动学停止：下一tick边界保持当前关节，停止再取汁/发新运动；空中液体在会话未暂停时继续。它不是硬件制动模型。先撤销代次再结束脚本；不能等待脚本回调才清理。

## 代码和步骤双入口

结构化流程IR只支持有限循环、技能调用、等待及受支持条件。步骤模式编辑IR并生成专用流程文件，携带节点ID→源码范围映射。用户自由修改后若无法无损解析，则切到代码模式，保留原文件；步骤面板只读显示支持的静态概览和真实执行事件。

源码定位使用`file_hash, line, column, skill_call_id, action_id`，事件由宿主采集；Python自报日志不作为控制状态真相。只读场景快照不暴露服务对象或真实文件句柄。

## 执行预算建议

开发基线可先设：单次不让出控制计算5s、单作业墙钟30min（暂停/等待可配置）、基础动作上限10000、日志每秒100条、单条4KiB、待准入动作最多1个；超额明确失败或限流。它们是配置建议，需原型评估，不是已测性能。模拟工艺等待使用仿真时间，不能被计算超时误杀；CPU忙循环和等待SDK采用不同看门狗。
