# 02 架构与模块设计

验证更新：可信代码→后端运动→正式网格→指定快照图像已在V0.11原型跑通，见07；本节完整技术选型仍未全部实测。特别是FastAPI、Monaco、MCP及Pyodide隔离未由本次原型验证。

## 总体结构

```text
桌面浏览器UI ──HTTP/状态流──┐
MCP适配器 ──应用服务调用────┼── 会话服务：唯一写入入口
代码运行宿主 ──能力受限RPC──┘      │
                                ├── 项目/版本存储
                                ├── 控制权/作业调度
                                ├── 轨迹规划与检查工作进程
                                └── 仿真核心：固定时钟、关节、液体
                                          │
                                     不可变快照
                                          ├── UI三维渲染
                                          ├── 独立截图工作进程
                                          └── 日志/回放/存档
```

UI和渲染器没有修改权威关节状态的能力。规划工作进程返回候选轨迹与检查报告，提交时由会话服务重新核对上下文。代码运行器不是仿真核心。

## 模块责任

| 模块 | 输入/输出 | 不应承担 |
|---|---|---|
| ProjectStore | 工作副本→不可变ProjectRevision、内容哈希 | 执行导入项目的脚本 |
| SessionService | 带身份请求→受理/错误/作业ID | 每个客户端各存一套仿真 |
| ControlArbiter | 观察会话、控制者、租约→能力代次 | 通过隐藏UI按钮代替服务检查 |
| JobSupervisor | 阶段、脚本、动作事件→生命周期 | 信任脚本自报成功 |
| Planner | 机器人/起点/约束→时间参数轨迹与报告 | 直接执行或修改场景 |
| SimulationCore | 检查后的动作＋dt→关节与液体状态 | 读取网页FPS或脚本墙钟当时间 |
| SnapshotStore | 不可变状态→版本化读取与订阅 | 返回“差不多”的当前状态代替指定帧 |
| ScriptHost | 固定代码版本→受限SDK请求与调试事件 | 获得宿主文件、主会话令牌或设备接口 |
| SceneRenderer | 场景描述＋快照＋相机→画面 | 自行重新解IK、重新推进液体 |
| McpAdapter | 工具参数→同一应用服务→标准工具结果 | 绕过控制权调用关节写入 |

## 候选技术与理由

| 部分 | 本轮选择/候选 | 验证状态 |
|---|---|---|
| UI | TypeScript、React、Vite；代码面板Monaco；共享三维包Three.js | 设计选择，未安装/锁版 |
| URDF显示 | `urdf-loader`及本地URDF/STL资源 | 官方项目提供Three.js加载实现，仍需本机验证 |
| 会话/核心 | Python、FastAPI，单写入事件循环；耗时规划分离 | 候选，与此前Python离线算法衔接 |
| 状态流 | WebSocket最新快照＋可靠事件游标 | FastAPI有官方WebSocket支持；本应用协议自行设计 |
| 项目/元数据 | SQLite事务＋内容寻址文件；文件先写临时再原子换名 | 单本地用户，减少服务依赖 |
| MCP | 官方SDK，首选本地stdio适配器连接已运行服务 | 不自行拼装一个同名REST接口冒充MCP |
| 截图 | Node/Playwright管理独立Chromium加载共享渲染页 | 官方支持截图；一致性及WebGL需实测 |
| 流程语言 | Python语法；受限SDK；首选验证Pyodide Worker运行方案 | 不承诺原生CPython全部功能 |

精确版本在首个技术原型通过后锁定；“官方stable文档”不等于本项目已验证某个版本。Monaco等尚未核对的细节不作为已证实能力承诺。

## Python隔离候选方案（阻断性ADR-01）

首选验证：独立Chromium进程中的专用页面＋模块Worker加载本地Pyodide。由本地ScriptHost管理，不依赖交互UI存在；源码只挂载到该运行的虚拟项目空间。

Pyodide官方示例展示Worker执行Python，但这本身不能证明沙箱满足我们的要求。必须同时具备：独立无凭据上下文、本地固定资产、禁止任意外连的CSP及宿主请求拦截、无宿主文件挂载、无Node集成、关闭下载/弹窗/新页和非允许协议、宿主超时终止，以及不绕过服务准入的能力RPC。Worker发出的消息也视为不可信。

不要将主服务令牌交给Python或Worker。受信宿主为该运行附加受限能力代次；服务只接受该运行、限定操作和预算内的请求。Python能构造SDK消息不构成越权，执行服务仍独立检查全部参数、控制权和取消代次。

限制模块导入和静态AST检查仅用于可用性/诊断，不能作为安全边界。Pyodide可能通过JS互操作访问浏览器能力；需专门验证绕过路径、资源耗尽、网络拦截和宿主终止。

若该方案不能满足CD08，改用有明确文件/网络/资源限制的容器或VM运行器并记录安装成本，不降级为直接`exec`宿主Python。技术验证未通过时禁用用户代码执行并如实报告，不以此宣布首版完成。

## 存储与部署

建议开发目录：`apps/web`、`packages/scene-renderer`、`packages/contracts`、`services/session`、`workers/planner`、`workers/script-host`、`workers/render-host`、`examples/soy-chicken`。这是目录设计，尚未创建应用。

初期macOS本地运行，服务仅绑定回环地址；用户一次启动服务，UI可关闭。状态和项目由服务存储；MCP适配器退出不关闭会话服务。启动器分别探测资源、存储、运行器和渲染器健康状态。

不要把当前Sites导出文件改造成完整运行器。旧导出附件及其iframe/CSP继续原样保留；完整工作台另建工程。

## 官方参考与继承边界

- [urdf-playground](https://github.com/xbsheng/urdf-playground)：参考URDF场景和控制交互。其README描述Three.js模型显示及Web Serial；本项目首版不继承串口链路。
- [URDF Loaders](https://github.com/gkjohnson/urdf-loaders)：Three.js URDF加载候选，不等于运动规划器。
- [Three.js文档](https://threejs.org/docs/)：共享渲染实现依据。
- [FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/)：状态通道候选。
- [Pyodide Worker](https://pyodide.org/en/stable/usage/webworker.html)和[兼容性](https://pyodide.org/en/stable/usage/wasm-constraints.html)：Python运行候选及兼容限制；不将Worker当作完整权限隔离证明。
- [Playwright截图](https://playwright.dev/docs/screenshots)：渲染产物捕获机制；帧一致性由本项目另行保证。
- [MCP服务开发文档](https://modelcontextprotocol.io/docs/develop/build-server)：兼容工具服务；stdio日志输出到stderr。
