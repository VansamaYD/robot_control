# 04 数据与接口设计

## 统一约定

这是协议草案，尚未实现服务。服务/SDK/MCP共用规范化模型；JSON只接受有限数值，拒绝NaN/Infinity、未知动作和额外敏感字段。内部SI单位，JSON字段显式后缀；无量纲数据也声明用途。

`schema_version="1.0-draft"`；未知主版本拒绝，迁移生成新对象不覆盖旧记录。对象ID不含可执行路径；资源按内容哈希解析。UTC时间用于审计，单调墙钟用于租约/超时，整数tick用于仿真，三者不互换。

## 数据实体

| 实体 | 必需内容 | 更新规则 |
|---|---|---|
| ProjectRevision | project_id、revision_id、manifest_hash、入口/文件哈希、技能/依赖版本 | 不可变；工作副本单独保存 |
| SceneRevision | revision_id、world_frame、机器人/工具/锅/鸡/点位、资源/近似模型和参数来源 | 编辑应用后新版本 |
| Session | session_id、incarnation、mode、health、clock、配置版本、所有者/代次、active_job | 单写者维护 |
| Plan | plan_id、输入指纹、配置/模型版本、起点条件、轨迹哈希、检查报告、覆盖分支和失效条件 | 不可变；不能直接改为“通过” |
| Run | run_id、固定运行清单、父流程/阶段关系、参数、随机种子 | 描述一次版本化执行 |
| Job | job_id、run_id、origin、principal_id、status、进度/当前动作、end_reason | 版本化事件驱动 |
| Action | action_id、seq、技能栈/源码位置、类型/SI参数、plan_id、状态 | 绑定运行及能力代次 |
| StateSnapshot | session/incarnation、state_revision、tick、配置、关节、液体、作业和来源/质量 | 不可变 |
| ImageFrame | image_id、快照标识、相机哈希、资源哈希、分辨率、PNG哈希 | 不可变 |
| RunRecord | 清单、事件、状态帧、外部加减汁、结束原因、图片引用 | 保存后只读 |

快照标识为`(session_id, incarnation, state_revision)`；不使用单一数字跨会话查帧。配置版本涵盖几何、工具、限制及模型；代码版本独立。相机描述/哈希属于图像请求，改变观察视角不使计划失效。

## 状态返回示例

以下数值仅演示格式，`joint_example`也只是字段示例，正式名称取自模型映射；不是SO-101实测/仿真结果。

```json
{
  "schema_version": "1.0-draft",
  "session_id": "session_demo",
  "incarnation": "boot_demo",
  "state_revision": 125,
  "configuration_revision": "scene_demo_2",
  "tick": 120,
  "dt_s": 0.02,

    "joint_name": "joint_example",
    "virtual_servo_id": 1,
    "target_position_rad": 0.5,
    "position_rad": 0.4,
    "velocity_rad_s": 0.1,
    "quality": "simulated",
    "current_a": {"value": null, "quality": "unavailable"}
  }],
```

快照附带采集墙钟与单调序号；客户端数据年龄基于服务报告与本地接收时间计算。暂停时tick不变但服务心跳正常，不能因此误判为状态陈旧。

## 应用API

基线`/api/v1`，下列为核心路由；DTO由同一Schema生成/校验。所有写请求必须有principal/能力与乐观版本条件。

| 操作 | 路由 | 语义 |
|---|---|---|
| 列项目/读取版本 | GET `/projects`、`/projects/{id}/revisions/{rev}` | 只读，分页 |
| 保存工作副本快照 | POST `/projects/{id}/revisions` | 文件路径约束＋内容原子提交 |
| 初始化会话 | POST `/sessions` | 加载固定资源，默认暂停；失败列出资源问题 |
| 读取状态/场景 | GET `/sessions/{id}/state`、`/scene` | 状态编号与质量，不隐式运动 |
| 应用场景编辑 | POST `/sessions/{id}/scene-transactions` | `expected_configuration_revision`比较交换；不匹配拒绝 |
| 取得/释放手动控制 | POST `/sessions/{id}/control/acquire`、`release` | 租约/代次；不强夺活动作业 |
| 规划/校验 | POST `/sessions/{id}/plans` | 短请求可等待，耗时用planning_job_id查询；不运动 |
| 启动代码或计划 | POST `/sessions/{id}/jobs` | entry_kind=`program|plan`；固定版本及幂等键，返回job/run ID |
| 点动 | POST `/sessions/{id}/jog` | 手动租约＋序号＋有效期；不接受无限队列 |
| 作业操作 | POST `/jobs/{id}/commands` | pause/resume/step_action/step_skill/step_tick/cancel/request_flip |
| 查询任务 | GET `/jobs/{id}` | 真实状态、结束原因和事件游标 |
| 帧渲染 | POST `/sessions/{id}/images` | 固定快照＋相机＋分辨率；可返回render_job_id |
| 运行存档 | POST `/runs/{id}/archive` | 归档依赖/日志；导出受限资源引用 |

取消某作业要求该作业所属身份或本地显式接管权限；不因使用相同session_id就可取消任意任务。重置/故障恢复是独立操作，需要无活动执行并显示影响，不能复用“继续”。

## 事件和状态流

WebSocket建立时给完整快照及事件游标。状态帧可丢中间帧、保最新；作业终态、动作完成、错误、版本变更是可靠事件，持久化并用递增`event_seq`补读。

重连带`after_event_seq`；游标仍在保留期则补事件，否则返回`RESYNC_REQUIRED`并取完整状态和任务。客户端不得按快照序号推断所有事件已收到。

## 幂等与提交

键作用域`(principal_id, session_id, incarnation, operation, idempotency_key)`；请求指纹包含入口类型、固定代码/计划版本、规范化参数与配置前提。相同键相同指纹返回原任务；相同键不同指纹返回`IDEMPOTENCY_CONFLICT`。

身份授权、已有键查询、新任务创建、控制权分配和键→结果绑定需串行化/事务。验证失败不消耗成功幂等键；接收成功但响应丢失可重试。保留期限与会话存档一致；过期键不得悄悄当全新重试，要求新键并明确提示。故障后查原作业再决定是否创建新运行。

## MCP映射

首版优先stdio，服务进程独立；适配器与服务通过本地认证通道通信。MCP暴露与实现的能力一致，工具发现可用但服务故障时调用返回明确错误。

| 工具 | 行为 |
|---|---|
| `get_capabilities` | 返回simulation、code、snapshots等状态及不可用原因；hardware/vision=false |
| `list_programs` / `get_program_revision` | 列可运行入口及固定版本，读取代码/参数Schema |
| `get_scene` / `get_robot_state` | 读取场景及指定/最新状态，响应明确实际快照 |
| `validate_program` / `plan_skill` | 静态/可确定分支检查；返回覆盖边界与计划或规划任务ID |
| `run_program` / `run_plan` | 同一作业启动服务；异步返回job_id；必须提供版本与幂等键 |
| `get_job` / `cancel_job` | 查询或取消有权限的作业 |
| `request_flip` | 触发同一倒汁/停靠/等待业务流程 |
| `confirm_operator_update` | 仅在等待状态提交已验证新场景和阶段计划；不能凭一句确认绕过检查 |
| `render_snapshot` | 指定快照和视角，返回图像内容块＋同帧结构化元数据；超时可返回渲染任务ID供后续查询 |

完整MCP名称与协议协商在SDK锁版后定稿；不假设每个客户端都支持相同图像或流特性，首个验收客户端需实测。MCP不提供任意源码写入/安装包、直接设置关节状态、修改保护规则或实机接口。

## 截图一致性

受理时固定快照和资产清单，渲染器仅从只读输入加载，等待所有资源完成、应用关节/液体/相机，再等待显式`frame_ready`握手后截图。返回图像哈希与该输入清单；不能仅睡固定毫秒数就认为渲染完成。

截图窗口在请求周期内固定保留快照；相机来自请求，不改变操作者视图。状态过期、资源缺失、GPU/渲染失败和预算超限分别报错。服务继续仿真时也只能渲染指定旧帧，不能换最新帧凑结果。

## 错误结构

统一`code, message, details, retryable, request_id, job_id?, snapshot_ref?`。字段错误给JSON指针；运动错误给关节/部件/动作及检查阶段。

至少包含：`INVALID_ARGUMENT`、`UNSUPPORTED_VERSION`、`ASSET_MISSING`、`CONTROL_BUSY`、`LEASE_EXPIRED`、`STALE_CAPABILITY`、`CONFIGURATION_CHANGED`、`START_STATE_CHANGED`、`NO_IK`、`COLLISION`、`LIMIT_VIOLATION`、`LIQUID_UNAVAILABLE`、`JOB_TERMINAL`、`IDEMPOTENCY_CONFLICT`、`SNAPSHOT_EXPIRED`、`RENDERER_UNAVAILABLE`、`SCRIPT_TIMEOUT`、`SCRIPT_DENIED`、`RESYNC_REQUIRED`、`SERVICE_FAULT`。MCP和HTTP仅做传输映射，不另定义不同业务含义。
