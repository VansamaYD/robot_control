# 05 场景、运动与液体设计

## 坐标与资源

世界坐标右手系：锅底内表面中心为原点，Z向上，+Y指向锅远侧；单位m。机器人URDF根坐标通过显式`T_world_base`连接；工具通过`T_link_tool`定义，不修改原URDF关节零位。

变换统一为列向量：`p_world = T_world_base · T_base_link(q) · T_link_tool · p_tool`。存储四元数用xyzw、归一化并校验，不混用欧拉角次序。汤勺TCP建议勺口中心，局部+Z为勺口外法向；历史离线模型的工具法向为局部+X时，必须用固定旋转显式转换，不能直接复用旧姿态数值。

导入资产生成统一RobotDescription：关节名称、轴、父子变换、限位及资源哈希。前端显示与后端FK从同一规范化描述加载。验收比较若干已知关节姿态下的连杆/TCP矩阵；URDF原始单位和网格缩放都必须记录。

锅/鸡/汤勺分别有visual、collision、displacement参数。锅壁碰撞用侧壁和底，保留开口；不能用实心整圆柱把勺子挡在锅外。液体为允许工具进入的介质，不作为禁止接触的固体碰撞物。

鸡视觉用简化网格，碰撞用保守包络，排液用位于锅内的独立封闭近似。汤勺碰撞区分勺柄、碗壁和容纳液体的空腔；底座、停靠支撑和接液盘均有可见且可检查几何。

## 初始场景

提供S_BASE（锅400×120mm、勺口50mm、液位80mm、鸡偏移50mm）和S_VARIANT（液位70mm、偏移30mm）。它们是假设夹具，不是餐馆实测数据。所有其他尺寸、模型与源版本纳入场景清单，加载时验证，不承诺两组条件都能完成同一路径。

初始化顺序：资源校验 → 统一模型 → 关节/工具映射 → 几何与液体初值 → 初始碰撞/限位检查 → 首帧快照 → 暂停就绪。失败停在可解释错误页；不运行旧硬件初始化逻辑，也不把原始编码器中心当关节零位。

## 规划与路径检查

1. 将点位引用解析到固定世界坐标；点位可跟随鸡局部坐标，但每次规划固定其引用版本。
2. 五轴目标支持位置＋可达法向约束；不支持的完整姿态约束立即拒绝。
3. IK使用当前位置为初值，限制相邻解跳变并校验最终FK误差；求解容差、迭代上限和失败原因写入报告。
4. 关节路径优先用于离开/准备段；勺口近鸡/液面段支持受约束TCP路径，逐点连续求解。
5. 时间参数化满足各轴速度/加速度约束；最终时间轨迹再次检查，不只检查原几何路径。
6. 最终检查覆盖自身碰撞、机器人/柄/勺与锅/鸡/支撑碰撞、限位及速度/加速度；明确忽略的相邻连杆对和允许接触，不使用全局“忽略锅”。
7. 核心准入比较配置、关节/工具、液位和相关物体状态；运动中每tick检查下一步状态，异常拒绝后续推进并记录失败。

初版离散检查建议同时限制关节步长和包络顶点世界位移，不只按固定50ms采样；对接近障碍的段自适应细分。具体阈值从几何最小间隙与性能测试决定。若未实现有证明的扫掠/连续碰撞，就明确标记离散近似，不能称为绝不会漏碰。

动力学先采用理想运动学跟随，UI当前值与目标/计划采样值分别定义；无电机模型时没有电流、温升和真实扭矩输出。

## 液体权威模型

采用五个体积账户：锅P、勺L、空中A、鸡表面C、洒漏S。另记累计显式加入I、移除O。每tick检查：

`P + L + A + C + S = V_initial + I - O`

每次转移同一事务一减一加，数值截断误差有记录，不通过无条件补锅掩盖误差。勺容量为几何/配置上限；spill是累计未回收账户，导出时可单独报告。

### 液面

定义锅内可占液截面积`A_free(z)=A_pot(z)-A_displacement(z)`，有效体积`V(h)=∫A_free(z) dz`。鸡排液几何必须位于锅内且截面积合理；初版可对声明的近似做固定精度数值积分，记录误差，形成单调查表，再二分反解h。

溢出时锅体积封顶，多余量进入S。改变鸡姿态重新算关系并保持实际汁量，必要时溢出；编辑液位则显式计算加入/移除汁量，不静默丢账。渲染液面使用鸡体遮罩/几何裁剪，不将汁面画在鸡体里面。

### 取汁

计算勺口姿态、空腔浸入比例、与锅内液区交叠，以及鸡/锅阻挡。简化目标量：`min(请求量, 容量余量, 可取汁量, 浸入条件允许量)`。按声明的入液/停留时间近似流量逐tick执行P→L，记录实际量。

请求量是目标，不是保证。若实际量不足，按技能配置选择明确失败或返回`partial`结果；流程代码必须显式处理，不能假装满勺。纯声明“进入取汁步骤”不触发自动装满。

### 倾倒

设θ为勺口法向与世界向上方向夹角，采用待标定近似`Q_out = k · max(0, sin(θ - θ0)) · f(L/capacity)`并对允许角度区间和最大流量截断；k单位m³/s，f无量纲。该式只表达定性关系，不是已验证的流体方程。

每tick最多流出勺中现有量，L→A。A由有体积权重的简化流束包记录：起点、初速度、重力、体积、生成tick/年龄；运动用固定步长/解析抛物线并做段碰撞，首碰鸡/锅/外部后A→C/P/S。装饰粒子不另记体积。

C按声明的简化附着/回流时常逐tick回流到P或S，受落点归属影响；不能当帧立即全部回锅。固定池上限时聚合流束并守恒；不能丢弃粒子同时丢失账目。

真实飞溅、黏度、沸腾、温度与熟化不建模；UI和日志显示该边界。

## 停靠与翻鸡

以显式技能阶段表达：结束当前允许边界动作 → 检查余汁 → 有条件倒回有效锅区 → 退出锅沿 → 进泊位 → 验证模拟支撑/停止 → waiting_operator。停靠路线必须按当前场景重算，旧离线坐标仅作候选，不硬编码保证成功。

支持按阶段保存剩余轮次等业务状态。操作者改鸡位置后创建新配置，更新鸡局部点位，检查液面/取汁空间、起点与后续路径，再显式启动新阶段。停靠失败不显示“可翻鸡”；纯仿真提示不构成人员进入实机区域的许可。
