# 07 链路验证结果与设计修订

日期：2026-11-03。对应原型`output/prototype/v11/`。本报告将已验证能力与完整产品要求区分。

## 验证链路

可信Python生成器`flow.py` → 运动请求 → 后端逐段IK/时间采样/简化碰撞检查 → 固定dt权威关节状态 → 正式URDF网格三维显示 → 指定历史快照重渲染PNG。

没有播放此前保存的整条轨迹：代码每产生一个动作，当前原型按实际起点重新求解该段。使用旧离线求解器前，加载当前固定提交的URDF，逐关节校验轴、原点变换和限位完全一致；不满足时加载失败。

## 已观察结果

- 正式模型加载15个visual实例，五个运动轴；原夹爪替换为假设的工具，鸡是简化形体。
- 六个动作完成，2270个20ms活动运动步，共45.4s；当前规划计算时间不计入仿真时钟。
- 浏览器9组验证通过：模型与暂停启动、暂停冻结、单tick、六动作及坐标一致性、幂等与取消规划、无交互UI历史帧截图、所有页面关闭后后台运动、未知帧/未授权写入拒绝、错误JSON形态与源文件访问拒绝。
- 动态画面采样各连杆世界矩阵与TCP，与后端同帧值比较；这是渲染/坐标一致性，不是机械臂精度或IK误差的物理测量。最终样本数和误差见机器可读报告。
- 关闭交互页面后，新建只读渲染页面加载指定旧快照，产生1280×720 PNG和快照元数据。返回图像不是拿当前状态替代历史帧。
- 原型引擎9项测试通过，包含实际IK目标、限位/简化路径检查、不可达拒绝、观察频率与dt解耦、快照副本及取消竞态。

机器可读证据：`../../prototype/v11/evidence/browser-report.json`，图片与元数据同目录。完整产品48组验收仍未执行完。

最终冷启动复测采样50帧，渲染TCP与后端差的最大值约1.85×10⁻¹⁶m，连杆矩阵元素最大差约5.55×10⁻¹⁶。这只说明同源运动学和渲染在浮点精度内一致，不能用于宣称实机达到该精度。19个下载资源的哈希全部匹配。环境为macOS 15.7.3 arm64、Python 3.13.4、NumPy 2.3.3、Chrome 156.0.8078.80；无界面测试采用SwiftShader软件WebGL，不作为GPU性能验收。汇总见`../../prototype/v11/evidence/verification-summary.json`。

## 发现与修正

| 发现 | 本轮处理 | 正式实现必须吸收 |
|---|---|---|
| 最初锅显示为圆柱，检查器使用球冠 | 将显示锅壁与液面半径改为同一球冠参数生成 | visual/collision/displacement共享SceneGeometry输入，分别生成各用途几何 |
| 事件名参数与动作name字段重名导致流程失败 | 修正事件接口，重新从冷启动执行全链路 | 结构化事件类型不要与业务字段同名；失败必须进入任务终态并给出原因 |
| 规划完成可能晚于取消 | 用控制代次阻止迟到规划提交；加入竞态测试 | 取消先撤销能力，再清队列/终止运行器；规划器本身不是授权边界 |
| 同一流程入口的源码和版本可能被读取成不同副本 | 当前服务启动时固定展示源码和哈希 | 正式版从不可变ProjectRevision加载代码及依赖，不在运行中读取工作副本 |
| 原型规划等待冻结时钟 | 如实限定为运动链路验证 | 液体接入前采用独立核心时钟，见下文 |

## ADR-02：统一几何模型

正式SceneGeometry包含带单位和版本的锅/鸡/工具参数，各自生成显示网格、碰撞近似和排液几何。UI不再另写一组锅半径/鸡偏移常量。检查报告附该几何版本；截图加载同版本参数。

URDF规范化描述在服务端一次生成，前端和规划器消费相同描述。遗留求解器允许短期复用，但必须有从URDF生成/核对变换的测试，不以手抄常量长期替代模型来源。

## ADR-03：运行代码的中间动作协议

原型证明可信生成器按动作边界驱动三维可行，并不证明异步Python沙箱。正式保留`async main`SDK候选，但SDK必须输出可序列化且可校验的ActionRequest，不能把Python对象或服务引用跨越边界。

至少携带`run_id、incarnation、control_epoch、action_seq、source_ref、skill_call_id、type、SI参数、expected_configuration_revision`。动作准入/完成/失败事件关联同一action_id。前端的执行行高亮来自这些事件而非猜测时间。

受信生成器继续作为开发测试驱动器；隔离验证通过前，UI任意代码执行按钮不可开放。正式异步SDK需要单独验证暂停边界和纯计算超时；不将本次生成器示例直接当作最终语言兼容承诺。

## ADR-04：规划期间时钟与状态

完整核心不因UI、脚本或规划器等待停止液体时间。为便于首次完整实现，建议执行策略：

1. 默认暂停状态编译/预检可确定的动作段，得到检查报告；然后显式启动时钟。
2. 运行中的动态分支可异步规划，机械臂在有效保持状态，液体继续更新。
3. 基于固定快照求候选，准入时重新验证液位/物体/起点等相关条件；不满足则拒绝或显式重算。
4. 如需冻结后规划，必须作为显式全仿真暂停，UI/MCP均显示，不隐藏暂停。恢复前重验。

固定dt决定数值演化；渲染速度不决定tick。仿真速度倍率只影响墙钟节奏；暂停、租约、脚本计算时限依各自时钟处理。

## ADR-05：帧渲染协议

本次验证了“相同场景代码＋固定状态＝可再生成一致几何”。正式RendererService接收包含模型/工具/场景资产、快照和相机的RenderRequest；等待资源与状态应用完成后发`frame_ready`，再捕获PNG。

快照在渲染完成或超时前保留；任务有上限和超时，失败不能用最新帧补偿。轨迹历史必须显式作为快照/RenderRequest输入，否则关闭UI后只可重建当前姿态，不能声称轨迹叠层逐像素一致。

本次测试是同一无界面浏览器中新建渲染页，不是正式独立渲染工作服务、MCP图像返回或跨GPU像素一致性验证。
