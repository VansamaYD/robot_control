# 运行规则与界面流程：需求补充 V0.9

日期：2026-11-03。状态：设计建议，尚未实现或执行验收。延续V0.7与V0.8；本轮补齐操作规则，不新增实机或真实视觉范围。

## 1. 本轮发现的缺口

| 缺口 | 不明确会造成什么问题 | 本轮建议 |
|---|---|---|
| 脚本和模拟器谁掌握时间 | 代码跑完但机械臂还没动，或暂停后脚本继续发动作 | 执行服务持有仿真时钟；运动调用等待实际完成 |
| 调试命令的粒度 | 下一步有时执行一行，有时执行整轮浇汁 | 区分下一动作、下一技能和单个仿真时间步 |
| 窗口关闭或客户端掉线 | 正常后台运行被中止，或无人持有的控制持续运行 | 区分界面连接与控制会话；独立定义断连策略 |
| 翻鸡后怎么恢复 | 沿旧路线碰到新位置的鸡 | 人工修改作为场景事务；重验并生成后续计划 |
| 代码、场景和项目谁保存 | 历史运行引用已被修改的文件 | 固定运行清单，引用不可变资源版本 |
| 仿真到底能证明什么 | 好看被误认为舀得准、实际设备能做 | 明确运动学、液体和动力学三类精度边界 |
| 版本需求叠加后旧文档怎么读 | PR09后置与新首版范围矛盾 | 提供唯一索引和覆盖关系，实施时按有效需求集合验收 |

## 2. 建议工作台布局

桌面布局以三维视图和代码为中心，面板可收起、调宽，不要求一次显示全部细节。

```text
┌────────────────────────────────────────────────────────────┐
│ 项目 / 版本   模式：仿真   就绪状态 / 控制者   运行 / 暂停 / 取消 │
├───────────┬──────────────────────────┬─────────────────────┤
│ 文件与技能 │ 三维视图                  │ 代码 / 步骤编辑器     │
│ 场景与点位 │ 相机、轨迹、坐标与碰撞显示  │ 当前调用与技能执行栈   │
├───────────┴──────────────────────────┴─────────────────────┤
│ 当前动作 / 时间轴 / 每轴状态 / 液量 / 日志 / 错误              │
└────────────────────────────────────────────────────────────┘
```

运行前显示将执行的项目版本、入口、参数和场景；运行时突出当前动作与控制者。错误点击后定位代码、技能和相关三维对象。电机状态表始终可快速打开，默认折叠不可用字段。

场景参数编辑进入草稿，点击应用才改变权威状态。修改预览与运行中场景视觉上区分，避免以为参数已经生效。

## 3. 代码执行契约

- 运行入口由项目声明；建议Python的`async main(robot, scene)`，SDK和语言方案仍需技术原型确认。
- `await robot.scoop(...)`等待技能及其内部动作完成；拒绝、取消、失败不能被当作成功返回。
- `robot.wait(seconds)`使用仿真时间；用户脚本不能用宿主睡眠推进或冻结模拟器。脚本纯计算耗时不计为工艺等待。
- `scene`默认是带版本的只读快照；最新观测通过明确的状态读取接口获取，不能在任意代码里隐式读到半更新数据。
- 首版单个流程串行提交动作，不开放脚本并发控制同一机械臂。未来多臂任务另行设计同步和资源锁。
- 技能执行前验证参数与前置条件；执行后返回结果、动作ID和完成时刻，而不是仅返回“已入队”。
- 推荐技能由`move_joints`、`move_tcp`、`wait`、读取快照等受控基础动作组成；脚本不可直接设置仿真关节状态来跳过运动。
- 手动瞬移或重置场景只允许在未运行且明确的编辑模式中使用，并产生新状态/配置版本。它们不属于可用于证明运动可行的轨迹。
- 动态分支运行时准入。预览只覆盖已解析的分支，界面显示覆盖范围；不能把一次代码预演称为所有分支都已校验。

## 4. 调试和生命周期

| 操作 | 精确定义 |
|---|---|
| 运行 | 固定源码、技能、资源、场景和参数版本，创建新run/job，再由执行服务准入 |
| 暂停 | 在一个完整仿真时间步边界冻结时间和物理更新；脚本运行器停止发起后续动作；当前运动保存进度 |
| 下一动作 | 从暂停处完成当前基础动作；若当前在动作边界则执行下一基础动作；然后再次暂停 |
| 下一技能 | 执行到当前技能返回；若当前在技能边界则执行一个技能；可随时暂停或取消，不默认完成整个循环 |
| 单个时间步 | 推进固定dt，状态与液体一起更新，然后再次暂停；无活动动作时也可用于观察液体 |
| 继续 | 上下文未变化时继续当前运行；配置变化则拒绝直接继续，转入恢复校验 |
| 取消 | 撤销旧运行器提交能力并清空所属未执行动作，按已声明的仿真停止策略结束当前动作；独立液体模拟是否继续由会话是否暂停决定 |
| 重跑 | 创建新运行；明确选择重置到初始快照，或从当前状态启动并重新校验；不偷偷重置场景 |

首版不默认承诺任意源码行断点、表达式求值与完整Python调试器；支持技能/动作边界暂停、执行位置和调用栈。代码错误要有文件、行号、调用栈和作业结束原因。

项目保存、运行存档、只读回放分别有独立状态。程序正常退出但还有未完成运动时不能标为任务成功；取消后捕获异常也不能重新获得旧任务控制权。

## 5. 断连、控制权与后台运行

推荐一个本地会话服务持有权威状态；UI、脚本运行器、MCP和截图渲染器均为独立客户端或工作进程。关闭UI不等于停止服务，也不等于关闭全部工作进程。

- 手动点动依靠有期限的控制租约；释放按钮、失焦、断连或租约失效即停止续发，在下一仿真时间步停止该点动，不积压增量命令。
- 已正式启动的自主仿真作业由服务托管；关闭UI或MCP连接断开时默认继续，重连可查run/job；启动前界面和接口均说明此策略。
- 自主作业占有控制权直到完成、失败、取消或明确交接。客户端重连后能观察任务，不因观察连接自动取得控制权。
- 显式暂停/取消仍通过服务执行。断开MCP网络请求不等于取消任务。
- 服务重启后终止旧执行上下文，历史活动运行标为`interrupted`结束原因，不自动续跑；重新运行需明确创建新任务。
- 截图渲染器崩溃不改变权威仿真状态。脚本运行器崩溃则终止该作业并撤销队列；仿真核心失效则会话进入故障，所有新动作拒绝。

以上是纯仿真默认策略，不直接沿用到未来实机。首版默认单本地用户，不引入多租户账号体系；本地接口仍需会话凭证、来源/路径约束和明确能力范围，不默认暴露到公网。

## 6. 停靠、模拟翻鸡与恢复

完整流程为：请求翻鸡 → 按勺内状态处理余汁 → 沿检查过的路线停靠 → 验证模拟停靠条件 → 等待操作者。

等待期间可以在界面旋转/移动鸡，也可修正液位。修改以事务应用，生成新配置版本，并检查初始穿插、体积账目及取汁空间。

“确认翻鸡”只确认编辑完成，不授权沿旧轨迹继续。系统生成恢复检查报告，包括鸡姿态、液位、取汁点/浇汁点引用及后续路径。如果存在不可达、碰撞或不满足取汁条件，则保持等待并定位原因。

首版建议：翻鸡作为一个明确任务阶段边界；当前阶段结束后，将剩余循环次数等显式业务参数传给新阶段，生成新计划和新作业。关联父流程与前阶段运行ID，不尝试恢复任意Python解释器内部状态。操作者确认新阶段后启动，MCP也不能绕过相同检查。

翻鸡/液位编辑属于场景更新；液体账目必须记录外部增减和编辑理由，不将人为加汁当作仿真自动生成液体。鸡姿态改变导致排液几何变化时应重算液面和溢出。

## 7. 项目、版本和记录边界

每次运行的固定清单至少包括：项目快照ID、入口和源码哈希、技能版本、SDK/仿真内核版本、模型与碰撞资产哈希、场景/工具/点位、参数、限制、随机种子及有效精度等级。

保存应原子提交：失败时保留上次可用版本，并提示未保存数据。导入先在暂存区检查Schema、文件路径、资源缺失、版本兼容和大小限制，通过后才能创建项目。禁止隐式执行导入项目中的安装脚本或自动运行代码。

日志、状态帧和图片均有有界缓存/存储策略。项目源码与已保存记录不能被缓存清理删除；快照过期后的截图请求返回明确错误。保存完整运行时将需要的资源或可验证引用一并归档，缺资源不可称为可复现。

数值复现以相同引擎/依赖/资产版本和声明容差为条件，不承诺跨GPU、跨版本图像逐像素相同。记录回放与重新执行比较分别显示，不能混为同一结果。

## 8. 仿真可信度边界

| 能力 | 首版承诺 | 不能由首版推出的结论 |
|---|---|---|
| 关节与轨迹 | 正确模型、单位、限位、时钟及采样/扫掠校验策略；明示碰撞近似与裕量 | 实机定位误差、机械挠曲和制动距离已验证 |
| 舀汁与倾倒 | 勺口姿态/浸入和液位影响可用量；倾倒与收支一致，参数可查 | 真实黏度、湍流、飞溅与每勺体积已标定 |
| 鸡与锅 | 外观、碰撞、排液几何分别定义并显示版本 | 肉体变形、熟化、热传递或食物安全已模拟 |
| 舵机状态 | 运动学状态可用；未建模电气字段不可用 | 电流、温度、堵转和真实负载可预测 |

默认每轴当前值可跟随规划轨迹；如启用简化跟随误差模型，应标记模型和参数。动力学、电机和热模型不是首版验收前提。舀汁失败/溢出必须可发生，不能为了演示成功自动补液。

## 9. 新增需求与验收追踪

以下均为建议P0运行规则，验收尚未执行。它们补足已有需求，不代表新增一套独立产品。

| ID | 需求 | 验收场景 |
|---|---|---|
| OP01 | 按第2节提供完整操作入口，草稿与生效场景明确区分 | OT01：编辑草稿不影响当前状态；应用后版本与三维一致 |
| OP02 | SDK动作完成、时间和只读观测遵守第3节 | OT02：暂停中等待不消耗仿真时间；失败动作不返回成功 |
| OP03 | 串行控制；不允许脚本直接跳变权威关节状态 | OT03：并发运动与直接写状态被拒绝，不破坏当前任务 |
| OP04 | 第4节各调试命令语义一致 | OT04：基础动作、技能、时间步三种步进分别验证；循环不意外全部执行 |
| OP05 | 运行中改码不影响当前版本；重跑明确起点 | OT05：改技能后旧运行保持原版；重跑分别校验两种起点 |

## 10. 进入开发前的最小技术验证

不继续无限扩大需求。下面四项采用窄范围原型验证，通过后合并成V1.0实施规格：

1. 正确机械臂模型与勺子：加载本地资源，完成一个关节动作和一个TCP动作，显示轨迹/碰撞与统一关节状态。
2. 代码闭环：一个项目、一份流程、两个技能，通过受控SDK驱动上述模型；能暂停、取消、定位执行位置，终止死循环不拖死界面。
3. 液体闭环：一个取汁点与一个浇汁点，可视化液面/勺内汁/倾倒，并校验账目和空取汁失败。
4. MCP闭环：指定已保存代码版本启动，查询任务与状态；关闭UI后获取对应快照的真实渲染图。

推荐先在当前macOS环境验证桌面浏览器组合；跨系统支持不先作承诺。Python语法/SDK实现、隔离机制、渲染进程与依赖选型需经过上述技术验证。验收设备、性能门槛及资源限额在实现基线中记录，不能把建议值当作已测性能。
