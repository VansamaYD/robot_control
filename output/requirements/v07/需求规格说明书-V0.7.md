## 2. 产品目标与完成标准

用户能在同一工作台中设置场景、观察实际三维机械臂结构、控制运动、编排流程、查看状态、执行仿真、分析错误并保存结果；模型能通过MCP使用同一状态和动作系统，并获得与状态一致的渲染图。

首版完成需要满足：

1. 不依赖实物机械臂即可完成端到端流程。
2. 使用准确关节几何与模型资源，不以既有二维骨架演示替代完整三维交付。
3. 场景参数改变会影响计算、碰撞和液面，不只是改变文字或覆盖旧动画。
4. UI和MCP经过同一计划、控制权及执行服务，不存在模型专用旁路。
5. 可导出场景、程序、日志、截图并重新打开/回放。
6. 错误、估算值、不可用值、陈旧状态和仿真假设清楚可见。
7. 首版MCP是真正可被兼容客户端发现和调用的服务，不是仅有同名REST接口或文档占位。

## 3. 优先级和范围

- **P0：**本轮首版交付必须具备的能力；不能用“后续可接”代替已确认的MCP交付。
- **P1：**增强能力，不影响首版完整仿真闭环。
- **P2：**实机、真实视觉或研究扩展。

| P0 | P1 | P2 / 不纳入首版 |
|---|---|---|
| 三维场景、参数、关节/TCP控制、轨迹校验、代码项目/技能管理及隔离执行、步骤编排、液体近似、状态、日志回放、截图、MCP | 更多机型、多个工件、更丰富材料/流体近似、远程Git协作、更多调参工具 | 真实舵机控制、真实摄像头闭环、热态保护验证、飞溅CFD、鸡肉熟化/软体仿真 |

P0中的液体不是科研级流体，状态监控不制造虚假的电流/温度实测值。软件控制按钮不是经过硬件验证的急停。

## 4. 使用角色和入口

| 角色 | 主要目标 | 入口 |
|---|---|---|
| 操作者 | 配置锅和鸡、点动、运行浇汁、请求停靠、观察结果 | 图形界面 |
| 调试者 | 查看坐标、轨迹、关节曲线、错误与回放 | 图形界面与导出数据 |
| 模型客户端 | 读取状态、规划技能、仿真、查看图像、查询任务 | MCP |

首版可以只支持单机单工作区。多个界面/MCP客户端可观察，但同一会话同时只有一个运动控制权所有者。

## 5. 核心用户流程

### U01：创建并观察场景
启动应用 → 加载默认场景 → 自由观察/切换视角 → 修改尺寸与摆位 → 应用参数 → 系统更新几何与场景版本 → 校验初始摆位。

### U02：手动调试
初始化仿真 → 取得手动控制权 → 关节点动或受约束TCP移动 → 预检查路径 → 执行 → 保存示教点。

### U03：配方执行
选择取汁与浇汁点 → 编排步骤 → 生成计划 → 预览并显示问题 → 启动 → 查看状态与汁量 → 暂停检查/继续或取消 → 保存记录。

### U04：停靠与模拟翻鸡
请求翻鸡 → 在适合的已验证边界响应 → 必要时倒回锅内 → 退出停靠 → 等待用户修改/确认鸡的位置 → 重新检查场景与计划 → 显式恢复。

“人工翻鸡”在首版是模拟器中的操作者交互。页面不得显示已允许真实人员进入设备区域。

### U05：模型闭环
MCP读取场景/状态 → 规划受限技能 → 启动仿真作业 → 获取对应状态截图 → 检查/修改计划 → 结束或请求停靠。

### U06：离线回顾
导入保存的运行记录 → 进入只读回放模式 → 拖动时间轴、看状态和错误 → 生成选定帧截图 → 退出回放后重新初始化，不能把回放指令发到实时会话。

## 9. 暂停、停止和翻鸡语义

| 操作 | 首版语义 |
|---|---|
| 暂停仿真 | 冻结模拟时间、机器人和液体状态，仍可转相机；用于观察，不代表实机安全停机 |
| 单步 | 分为下一基础动作、下一技能、单个仿真时间步，按钮明确标识；具体规则见V0.9 |
| 取消作业 | 不再开始后续步骤，按声明的模拟停止策略结束当前运动；清除旧作业队列，液体可继续演化 |
| 请求翻鸡 | 业务请求，在合适边界执行倒回/停靠流程；不是故障急停 |
| 注入故障 | 进入明确故障状态，按模拟策略处理；不能自动完成剩余配方 |
| 确认翻鸡完成 | 需要在等待操作者状态，确认新场景并重新验证后才继续；普通关窗/点击场景不代替确认 |

## 13. 状态和版本契约

至少区分：

- 模式：simulation、replay；首版无hardware模式入口。
- 控制权：none、manual、program、mcp，只有一个所有者。
- 作业：draft、validated、queued、running、paused、waiting_operator、succeeded、cancelled、failed。
- 运行健康：uninitialized、ready、stopping、fault等，可与作业状态分别描述。

数据对象至少包含Scene、RobotModel、ToolProfile、Waypoint、Recipe、Plan、Job、StateSnapshot、ImageFrame、RunRecord。术语和枚举在API设计阶段统一，不能让UI和MCP各有不同解释。

`configuration_revision`覆盖影响计划的几何、标定、工具和限制；`state_revision`表示不可变快照；`camera_revision`表示观察视角。相机变化不让运动计划失效。启动检查使用实际相关起始条件，不能因为无关时间戳变化就拒绝，也不能忽略关节/液位变化。

| MC06 | P0 | render_snapshot返回真正的PNG图像及对应状态/相机元数据，兼容客户端可看到图像 |
| MC07 | P0 | 所有动作同样受控制权、场景版本、起始条件、限位和轨迹检查约束 |
| MC08 | P0 | 缺字段、越界、过期计划、忙碌、无IK、碰撞、无快照、渲染器不可用分别有可识别错误 |
| MC09 | P0 | 初始默认无控制权；模型获取控制权遵守会话规则，不提供解除保护或实机使能工具 |
| MC10 | P0 | 模型可完成“读状态→规划→运行→取图→查结果→结束”的一次实际客户端闭环 |

工具名称是需求草案，实施时可以统一调整；语义、数据质量和验收结果不能因改名丢失。

## 17. 性能、运行和测试基线

以下为建议目标，需记录验收机器与场景负载；不是当前实测结果。

| 指标 | 建议目标 |
|---|---|
| 场景负载 | 单SO-101、一锅一鸡、一把勺、一个泊位；资产大小和三角形数记录在验收报告 |
| 显示 | 上述场景下常规交互目标≥30FPS，争取60FPS；记录低帧原因，不用降低仿真步数伪造速度 |
| 状态 | 本地UI/MCP至少可获得20Hz级最新状态流或快照能力；并非所有电机类字段均20Hz |
| 操作响应 | 正常本地操作受理目标200ms内；计划完成和截图另有异步/超时语义 |
| 截图 | 1280×720预置视角，渲染进程预热后目标3秒内；记录实际设备、冷启动和失败情况 |
| 存档一致性 | 保存重开后场景/配方/版本一致；同一记录和种子可重建一致的数值状态 |
| 长流程 | 建议连续仿真30分钟，无失控队列增长、作业重复执行或液体账目崩坏 |

初期支持一个明确选定的桌面浏览器与操作系统组合，再扩大兼容性。网络依赖应锁版本；核心模型资源本地提供，断网不影响已有场景仿真。模型调用服务是否需要网络由客户端决定，不把它作为模拟器必须联网条件。
