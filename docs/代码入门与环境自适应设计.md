# 流程代码入门与环境自适应设计

2026-11-03。依据当前0.15实现。本文是解释与下一阶段设计，没有新增可编辑场景、摄像头识别或动态避障实现。

## 1. 当前路线能适应什么

当前flow.py包含绝对位置。每段从实际模拟关节状态出发重新求解FK/IK和时间轨迹，执行运动及简化碰撞检查；不是只播放保存的关节动画。

但环境依然固定：鸡的位置/尺寸来自SCENE初始化；碰撞近似仍限制S_BASE并在加载时检查假设。液位会按收支变化，取汁坐标Z=75mm、浇汁坐标Z=195mm不会随之自动调整。不能仅拖动画面里的鸡或改文字参数，就称为模型已经自适应。

| 变化 | 固定绝对点可能出现的问题 | 应采取的更新 |
|---|---|---|
| 蒸发、取用、补汁造成液面变化 | 勺沿无法进液、量不足；盲目降低又可能碰锅底/锅壁 | 更新实测/输入液面与汁量，重选完整勺体可放入的区域和深度 |
| 鸡更大或摆得更高 | 取汁通道消失，浇汁点进入鸡体，勺柄/连杆碰撞 | 更新外形、顶部、可见面、碰撞与排液模型 |
| 鸡平移或转动 | 浇到旧位置，原路线穿过新位置 | 更新鸡坐标变换并重建相关路径 |
| 人工翻鸡或鸡变形 | 原来鸡背上的点变到下面，刚体坐标变换不足以描述 | 重新识别/确认当前暴露表面，再生成浇汁点 |
| 锅或底座移动 | 全部相对位置失效 | 重新确认锅/底座/相机参考坐标及对应配置版本 |

固定路线只在摆位、几何和误差都受约束的工况内可作为已验证方案。发生变化后，要验证剩余路径，而不是只移动最终浇汁点。

## 2. 建议分成三层

**任务层**描述动作顺序，例如一轮取汁、浇三个部位、排汁停靠。它不必因为鸡移动20mm就整体重写。

**目标层**根据当前场景解释“取汁区”“当前露出的鸡背/胸面”“锅内排汁区”。取汁点相对锅和液面生成；鸡表面目标相对当前可见几何生成；停靠点相对固定工位/支撑位置生成。

**轨迹层**根据关节起点、工具、约束和场景版本重新规划，并检查完整勺体、柄和机械臂。不存在满足条件的区域时，明确拒绝并请求调整工况。

建议流程：获取观测/人工输入 → 更新统一场景 → 选择语义目标 → 生成轨迹与液体预演 → 执行前核对 → 执行一段 → 再次观测。变化没有被检测和更新时，任何规划器都无法对真实新位置做可靠检查。

## 3. 液位和取汁点怎么求

以勺口中心为TCP，保持勺口近似向上。几何候选可以先取：

`z_pick = liquid_height - rim_submersion`

例如液面80mm、勺沿浸入5mm，候选Z=75mm；液面降至60mm，候选Z=55mm。后者只是候选，不表示一定可达或不会碰撞。

还必须检查：球冠锅在该深度的截面、整个碗体及柄、鸡占据的空间、关节可达性、工具朝向、误差与停止裕量。自由空间不足时，应重新选择XY、改变取量/工具或要求人工处理，不能不断下降去碰锅底。

候选区域可用锅内网格/采样搜索，优先距离锅壁和鸡更远且关节变化小的位置。目标量达到后提起，但提起过程中可能自然流回或洒漏，离锅后的实际量仍要反馈核验。0.15的最低量检查不等于精确30mL计量。

真实液位不能只依赖当前理想账目：蒸发、额外加汁和人工操作会改变总量。首轮可人工输入/确认，后续增加液位观测。称重只直接给质量，锅、鸡质量及排液关系仍需处理，不能直接把总重量当液位。

## 4. 浇汁点怎么求

可先用“当前鸡表面上方一段距离”的候选，浇汁高度相对实际表面生成；再检查出流点及落点，而不只检查TCP。

汤汁从最低勺沿离开，出口相对勺口中心存在偏移，且随倾角变化。当前模型用简化弹道预测落点。TCP对准鸡背中心并不自动意味着液流落在同一点。

移动鸡时，鸡局部的采样目标可随变换移动；翻鸡后必须重新筛选暴露在上方的可见表面，不能把旧鸡背点机械地变换到底面仍继续浇。柔性食材会变形，刚体姿态与椭球包络只是初步近似。

## 5. 先做低成本的分段自适应

建议第一步在纯仿真中实现：人工输入/拖动鸡的位置、大小、方向及液量；统一更新显示、碰撞、排液模型和版本；点击重新规划。先验证这套闭环，再接摄像头。

固定锅位和底座，控制鸡的放置范围，可以减少不确定性；配合每轮/翻鸡后的人工确认，能先降低原型复杂度。这里不增加新的硬件采购承诺。

后续固定相机可先观察二维轮廓/位置。普通单目图像不能凭轮廓直接得到可靠绝对高度；需要相机标定、锅/工位坐标，以及深度、已知高度或保守人工估计。蒸汽、反光、遮挡和置信度都应进入状态质量，不能让模型根据一帧模糊图直接改舵机目标。

## 6. 运动途中变化怎么办

首版建议分段处理：取汁前更新液位；浇汁前确认鸡表面；翻鸡后创建新配置并重验后续路径。小幅、缓慢变化可在明确边界重算下一段。

如果鸡突然滑动或人员进入，不能假定任意中途撤退都安全。应在已验证停止策略下停止/保持，刷新观测后重算；数据陈旧、低置信度、变化过大或无安全路线时等待人工处理。不要在旧轨迹上直接把终点跳到新坐标。

裕量应包含相机/模型/关节误差，以及观测时延内物体可能移动的距离，并结合系统停止包络设计；不是随意设置一个固定5mm就完成保护。实机停止和人员防护仍需独立验证。

持续视觉伺服比段间更新复杂，涉及同步、时延、稳定性、奇异位形及动态碰撞；不建议把它作为当前低成本首个目标。MCP/模型适合提出高层技能或目标，执行服务负责准入、规划和约束。

## 7. 当前Python逐行读法

当前默认流程是：

```python
def main(robot):
    yield robot.scoop('等待自然取汁 ≥30mL', 30, .7)
    yield robot.move_tcp('提勺', [0, -0.100, 0.195], [0, 0, 1], 12.2)
    yield robot.move_tcp('移到鸡背上方', [0, -0.020, 0.195], [0, 0, 1], 6.5)
    yield robot.move_tcp('倾斜汤勺 65°', [0, -0.020, 0.195], [0.906307787, 0, 0.422618262], 5.0)
    yield robot.wait('保持倾角淋汁', 2.5)
    yield robot.move_tcp('汤勺回正', [0, -0.020, 0.195], [0, 0, 1], 4.0)
    yield robot.move_tcp('返回取汁上方', [0, -0.100, 0.195], [0, 0, 1], 6.5)
    yield robot.move_tcp('下降到取汁点', [0, -0.100, 0.075], [0, 0, 1], 12.2)
```

| 写法 | 含义 |
|---|---|
| `def main(robot):` | 定义名为main的流程函数；robot是执行环境提供的动作描述接口 |
| 缩进 | 表示下面这些行属于main，不是格式装饰 |
| `yield` | 生成并交出一个步骤；Python生成器保留当前位置，取下一步时继续 |
| `robot.scoop(...)` | 描述保持/等待与最低量核验，不是启动泵 |
| `robot.move_tcp(...)` | 描述勺口中心的位置、勺口朝向及本段运动时长 |
| `robot.wait(...)` | 描述保持当前位置并让仿真时间继续；不是全仿真暂停 |

特别注意：yield本身不会等待机械臂完成，也不控制硬件。当前Robot方法返回字典，yield把字典交给收集者；后端的检查、调度和等待队列完成，才产生“这步结束再执行下一步”的行为。

默认可信flow.py会在服务启动时被收集为版本化JSON；平时UI执行的是已保存动作列表，Python面板是对应代码视图。任意Python编辑/隔离执行尚未实现。

### 一行move_tcp拆开看

```python
yield robot.move_tcp(
    '提勺',                  # 说明文字
    [0, -0.100, 0.195],      # 世界坐标[x, y, z]，单位米
    [0, 0, 1],              # 勺口向上的单位法向，不是关节角或欧拉角
    12.2,                   # 本段运动的仿真时长，单位秒
)
```

世界原点为锅底内表面中心，Z向上，+Y为锅远侧。因此这行目标为X=0、Y=-100mm、Z=195mm。它不是“先等12.2s再开始”，而是让这一段轨迹用12.2s执行；计算另计，8×预览时运动墙钟约1.525s。

机器人有五个运动轴，执行器通过IK算各关节角；你不需要在这行手动写五个舵机角。也不能据此假定五轴能达到任意六维姿态。

倾倒行的法向约等于`[sin(65°), 0, cos(65°)]`，表示勺口向世界+X方向倾斜65°。三个数不是三个角度。

`scoop('...', 30, .7)`表示保持/等待0.7s并检查至少30mL；自然交换可能装到约32.7mL。`wait('...', 2.5)`保持2.5s，让液体继续流，不会停止物理时钟。全流程动作时间共49.6s，不包括规划墙钟。

## 8. 以后代码应该怎样表达

以下只表示下一阶段接口意图，当前不可直接执行：

```python
def main(robot, scene):
    pick = scene.select_free_liquid_region(minimum_ml=30)
    pour = scene.select_exposed_chicken_surface(region='upper_body')
    yield robot.scoop_at(pick, minimum_ml=30)
    yield robot.pour_on(pour)
    yield robot.dock_after_verified_drain()
```

这里“取汁区/暴露表面”稳定表达任务，但坐标来自当前场景。目标对象必须带坐标系、观测时间、质量及场景版本。执行前再次核对，改变场景就使旧相关计划失效。

建议落地顺序：共享可变场景 → 参数编辑与版本事务 → 自由取汁区搜索 → 表面目标和出流落点 → 段间变化/失效演练 → 相机观测接入。不要先做摄像头画面，再继续用旧固定碰撞模型执行。
